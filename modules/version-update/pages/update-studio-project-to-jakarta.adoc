= Update a Bonita Studio project to Jakarta EE
:description: What Bonita Studio migrates for you, and what you must change yourself, when you open a project in Bonita {bonitaVersion} and its Jakarta EE runtime.

{description}

Bonita {bonitaVersion} runs on Tomcat 10.1 and implements the Jakarta EE APIs. The `javax.*` packages of Java EE (servlet, persistence, XML binding...) are renamed `jakarta.*`, and Groovy moves from version 3 to version 4, whose Maven coordinates changed from `org.codehaus.groovy` to `org.apache.groovy`.

When you clone or import a project from a previous version, Bonita Studio migrates the Maven configuration of the project and of its extensions. It does not rewrite your Java or Groovy source code: this part is manual.

[#migration-notes]
== Read the migration notes first

The changes Bonita Studio applies, and the actions it leaves to you, are listed in the `MIGRATION_NOTES.adoc` file generated at the root of the project (see xref:update-studio.adoc[Updating Bonita Studio]).

Look for the lines starting with *Action required*: each of them names a file or a pom section that Bonita Studio did not change.

[#automatic-changes]
== What Bonita Studio migrates for you

=== Servlet API in REST API extension poms

In every REST API extension project, the `javax.servlet:javax.servlet-api` dependency is replaced by `jakarta.servlet:jakarta.servlet-api`, in the `provided` scope and without version: the version is managed by the Bonita runtime BOM.

A `javax.servlet-api` version pinned in the `dependencyManagement` section of the extension pom is removed, since it would override the runtime BOM.

Before:

[source,xml]
----
<dependency>
    <groupId>javax.servlet</groupId>
    <artifactId>javax.servlet-api</artifactId>
    <scope>provided</scope>
</dependency>
----

After:

[source,xml]
----
<dependency>
    <groupId>jakarta.servlet</groupId>
    <artifactId>jakarta.servlet-api</artifactId>
    <scope>provided</scope>
</dependency>
----

[NOTE]
====
Dependencies declared inside a Maven `<profile>` are not migrated: a profile can hold the configuration of an older runtime. Bonita Studio reports them in the migration notes so that you can update them yourself.
====

=== Groovy 4 coordinates

In the project pom and in every extension pom, the Groovy dependencies move from the `org.codehaus.groovy` group to the `org.apache.groovy` group. Their versions are inherited from the Bonita runtime BOM.

* `groovy-all` is replaced by the individual Groovy modules the runtime provides.
* `groovy-servlet` is removed: the Bonita runtime no longer provides it.
* A Spock version written by a previous Bonita archetype or migration is moved to its Groovy 4 variant (`-groovy-4.0`).

Before:

[source,xml]
----
<dependency>
    <groupId>org.codehaus.groovy</groupId>
    <artifactId>groovy</artifactId>
    <scope>provided</scope>
</dependency>
----

After:

[source,xml]
----
<dependency>
    <groupId>org.apache.groovy</groupId>
    <artifactId>groovy</artifactId>
    <scope>provided</scope>
</dependency>
----

=== New extensions

REST API extensions, connectors and actor filters created from Bonita Studio {bonitaVersion} are generated from the Jakarta versions of the xref:software-extensibility:software-extensibility.adoc[Maven archetypes]: they already declare the `org.apache.groovy` coordinates, and `jakarta.servlet-api` for REST API extensions.

[#manual-changes]
== What you must change yourself

=== Imports in your extension sources

Replace the `javax.*` imports of the renamed Jakarta EE packages with their `jakarta.*` equivalent in the Java and Groovy sources of your extensions. For a REST API extension, it is at least the servlet API used by the `doHandle` method:

Before:

[source,groovy]
----
import javax.servlet.http.HttpServletRequest
import javax.servlet.http.HttpServletResponse
----

After:

[source,groovy]
----
import jakarta.servlet.http.HttpServletRequest
import jakarta.servlet.http.HttpServletResponse
----

Bonita Studio flags these imports in the sources of REST API extensions: a *Jakarta migration* warning is shown in the editor and in the *Problems* view, next to the compilation error.

[IMPORTANT]
====
Only the Java EE packages are renamed. The packages that belong to the Java SE platform keep their `javax` name, for example `javax.sql`, `javax.naming`, `javax.net` or `javax.crypto`. Do not rename them.
====

Packages most often found in Bonita extensions:

[cols="1,1"]
|===
|Bonita 2026.2 and earlier |Bonita {bonitaVersion}

|`javax.servlet`
|`jakarta.servlet`

|`javax.persistence`
|`jakarta.persistence`

|`javax.xml.bind`
|`jakarta.xml.bind`

|`javax.activation`
|`jakarta.activation`

|`javax.annotation.PostConstruct`, `PreDestroy`, `Resource`, `Generated`
|`jakarta.annotation.PostConstruct`, `PreDestroy`, `Resource`, `Generated`
|===

If your extension embeds a third-party library compiled against `javax.servlet` or another renamed package, upgrade it to a Jakarta-compatible version: the Bonita runtime no longer provides the `javax` APIs.

=== Business Data Model

The BDM client classes generated by Bonita Studio now use `jakarta.persistence`. Bonita Studio regenerates them, no action is needed on the BDM itself. Code of yours that imports `javax.persistence` directly, for example in a REST API extension, must be updated as described above.

=== Spock versions you chose

A Spock version that you set yourself, rather than one written by a Bonita archetype, is not changed. Spock publishes one artifact per Groovy major version, and the `-groovy-2.x` or `-groovy-3.0` variants do not run on Groovy 4: switch to a `-groovy-4.0` variant. The migration notes list each Spock dependency concerned.

=== Usages of groovy-servlet

If your code used classes of `groovy-servlet` (`groovy.servlet.*`), Bonita Studio removed the dependency during the migration. Remove these usages, or embed a Jakarta-compatible version of the library in your extension.
